# 2026-04-15 — Визуализация графа и метаграфа

## Задача
Получить минимальное, но информативное графическое представление
семантического графа и метаграфа, чтобы можно было визуально оценивать
качество выделения клауз, построения графа и агрегации.

## Гипотеза
Если каждый артефакт pipeline сопровождается self-contained HTML-страницей,
открываемой двойным кликом, и параллельно DOT-файлом для статичной вставки в
диплом, то цикл обратной связи «правлю правило → запускаю → смотрю результат»
сократится с минут (читать JSON) до секунд (открыть `.html`).

## Что сделано
- Новый модуль [src/metagraph_nlp/viz/](../../src/metagraph_nlp/viz/):
  - `palette.py` — детерминированная палитра по `md5(key)`, без зависимостей.
  - `dot.py` — чистые функции `graph_to_dot`, `metagraph_to_dot`. Не пишут на
    диск, не требуют установленного бинарника `graphviz`.
  - `html_pyvis.py` — `render_graph_html`, `render_metagraph_html`. Используют
    `pyvis` (vis.js) для self-contained HTML с тултипами и draggable-узлами.
- Двуслойная отрисовка метаграфа (CLAUDE.md §4.4):
  - метавершины — большие квадраты, окрашенные `palette.color_for(mn.id)`;
  - обычные узлы — окрашенные цветом своей метавершины;
  - сплошные стрелки — рёбра-предикаты;
  - **пунктирные `contains`-рёбра** от метавершины к её членам — явное
    визуальное выражение §9.4 (no silent collapse).
- Тултипы на каждом элементе содержат `provenance.rule` — это и есть
  «explainability first» из §7.4 в визуальной форме.
- Подключение к pipeline сделано опциональным: флаг
  `write_pipeline_artifacts(..., viz=False)`, флаг `--viz` в CLI. По умолчанию
  HTML/DOT не генерируются — старые тесты thin-slice остаются быстрыми.
- Импорт `pyvis` в `io/artifacts.py` ленивый: модуль тащит `ipython` и
  стартует ~150 мс, незачем платить за это в обычных запусках.
- Тесты: 4 unit-теста для `viz` (DOT contains all nodes, metagraph dashed
  contains-edges, два теста на запись HTML) + 1 integration-тест на запись
  четырёх viz-артефактов через CLI-pipeline.

## Результат
Все 12 тестов проходят (старые 7 + 4 unit viz + 1 integration viz). На
`data/samples/short.txt` создаются `semantic_graph.html`, `metagraph.html`,
`semantic_graph.dot`, `metagraph.dot` рядом с прежними JSON-артефактами.
В метаграфе видно три цветных метавершины-клаузы и шесть малых узлов,
каждый соединён пунктирной `contains`-связью со «своей» метавершиной.

## Ограничения
1. Метарёбра пока пустые (на уровне 1 их нет в данных). Рендер для них уже
   написан и сработает автоматически, как только появятся первые `MetaEdge`.
2. Многоуровневая дендрограмма (level >1) пока не визуализируется отдельно.
   Когда появится второй уровень агрегации, нужно будет либо ввести
   subgraph-кластеры в DOT, либо отдельные «слои» в pyvis (groups).
3. Раскраска по типу предиката или семантическому классу не делается — это
   станет осмысленным только после внедрения UD-парсера и нормализованных
   ролей.
4. pyvis тянет `ipython` (~10 МБ); это терпимо для исследовательского
   проекта, но если станет проблемой — можно заменить на чистый шаблон vis.js.
