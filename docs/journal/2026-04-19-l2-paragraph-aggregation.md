# 2026-04-19 — L2-параграфная агрегация + topic_overlap

## Задача
Реализовать первый шаг уровня 2 в метаграфе: метавершины уровня 2,
построенные линейно-лингвистическим правилом «один параграф → одна
метавершина». Параллельно ввести новый тип L2-метарёбер `topic_overlap`
(пересечение L1-фрагментов между L2-метавершинами) как инфраструктуру
для будущих L2-стратегий, где метавершины будут пересекаться по клаузам.

## Гипотеза
- параграфная стратегия даст простую и объяснимую L2, не опираясь на
  шаткие UD-признаки (субъект, кореференция);
- механизм `topic_overlap` корректно заработает «на потом»: на чистой
  параграфной стратегии он детерминированно вернёт 0 рёбер (параграфы
  партиционируют клаузы), но как только появится вторая L2-стратегия
  (кластеризация по shared_entity или агрегация по протагонисту),
  `topic_overlap` начнёт связывать пересекающиеся L2-агрегаты без
  доработки логики. Аннотируемая метаграфовая модель Гапанюка этому не
  препятствует: анти-аннотируемость не выполняется — один L1-элемент
  может принадлежать нескольким L2-метавершинам.

## Что сделано

### Сегментация
- `Sentence.paragraph_index: int` (дефолт 0) — новое поле в доменной
  модели. Параграф задаётся явно, а не восстанавливается из текста каждый
  раз.
- `split_sentences` теперь сканирует `\n\n` в `document.normalized_text`
  и присваивает `paragraph_index` через `bisect_right`. Нормализатор уже
  схлопывает 3+ `\n` в ровно два, так что граница параграфа однозначна.

### Агрегатор `paragraph_clauses_v0`
- Новый файл `aggregators/paragraph_metanodes.py`. Функция
  `aggregate_clauses_to_paragraphs(metagraph, clauses, sentences, ids)`
  группирует L1-метавершины уровня клаузы по `paragraph_index` своего
  предложения, для каждой группы создаёт `MetaNode(type="paragraph",
  level=2, label=f"paragraph_{k}")`.
- Фрагмент L2-метавершины содержит **не L0-узлы, а L1-метавершины**
  (`fragment.meta_node_ids`) — это прямое следование модели Гапанюка:
  `mv = ⟨{attr}, MG_f⟩`, `MG_f` может содержать другие метавершины,
  что даёт настоящую дендрограмму.
- Provenance: `rule="paragraph_clauses_v0"`, `inputs=[…L1-ids, …sent-ids]`,
  `notes="paragraph_index=k"`. 6 юнит-тестов на фейковых данных
  (несколько параграфов, одна клауза на параграф, мутация meta_nodes,
  детерминизм).

### Агрегатор `topic_overlap_v0`
- Новый файл `aggregators/topic_overlap_metaedges.py`. Функция
  `build_topic_overlap_metaedges(metagraph, ids, *, min_overlap=1)`:
  для каждой пары `(a, b)` L2-метавершин при `a.id < b.id` ищет
  пересечение `a.fragment.meta_node_ids ∩ b.fragment.meta_node_ids`; если
  `|shared| ≥ min_overlap`, создаёт `MetaEdge(type="topic_overlap",
  level=2, relation=f"overlap_{k}")` с `provenance.inputs=sorted(shared)`.
- 6 юнит-тестов, в том числе «канарейка» на параграфной стратегии
  (disjoint fragments → пустой результат) и проверка работы механизма на
  искусственно пересекающихся L2-фрагментах.

### Конфиг и pipeline
- `AggregationConfig.paragraph_enabled`, `.topic_overlap_enabled`,
  `.topic_overlap_min_overlap`. `configs/default.yaml` обновлён.
- `pipeline.run` получил две новые условные стадии после `shared_entity`:
  `paragraph_clauses_v0` → `topic_overlap_v0`. Обе пишут в `AuditLog`.

### Viz
- `metagraph_to_dot` и `render_metagraph_html`: толщина рамки
  метавершины зависит от `level` (L1 — тоньше, L2 — жирнее); `contains`-рёбра
  теперь отрисовываются и для `fragment.meta_node_ids`; `topic_overlap`
  метарёбра — синий пунктир, чтобы визуально отличать от `shared_entity`.

### Тесты
- 42 юнит-теста (было 24 → добавлено 16: 6 paragraph_metanodes, 6
  topic_overlap, 4 segmentation). Все зелёные.
- Интеграционный `test_thin_slice.py` обновлён: проверяет наличие
  `level=2`-метавершины `paragraph_0`, присутствие `paragraph_clauses_v0`
  и `topic_overlap_v0` в audit log, отсутствие `topic_overlap` рёбер на
  параграфной стратегии. 5 slow-тестов зелёные.

## Результат
`PYTHONPATH=src python -m metagraph_nlp process --input
data/samples/multi_para.txt --out artifacts/run_l2 --viz` на новом
3-параграфном sample-тексте:

- 6 предложений → 7 клауз;
- 15 L0-узлов, 8 L0-рёбер;
- 10 метавершин: **7 × L1 (clause) + 3 × L2 (paragraph)**;
  - `paragraph_0` содержит `mnode_000001..3`,
  - `paragraph_1` — `mnode_000004..5`,
  - `paragraph_2` — `mnode_000006..7`;
- 7 L1-метарёбер `shared_entity`, 0 L2-метарёбер `topic_overlap`
  (параграфы не пересекаются — ожидаемо).

Visual в `artifacts/run_l2/metagraph.html`: жирные прямоугольники L2
со стрелками-`contains` к L1-клаузам; topic_overlap-рёбер нет.

## Ограничения
1. **`topic_overlap` на параграфной стратегии всегда пуст**. Это не баг,
   а свойство параграфного разбиения. Рёбра появятся, когда добавится
   вторая L2-стратегия (см. «следующий шаг»).
2. **Границы параграфов — только `\n\n`**. Заголовки, маркированные
   списки, цитаты пока не различаются.
3. **Нет generic multi-round runner**. Все L2-агрегаторы пока пишутся
   точечно и явно вызываются в `pipeline.run`. Обобщать будем, когда
   появятся 2–3 стратегии и станет ясна их общая сигнатура.
4. **L2-метавершина не имеет содержательной метки**, только
   `paragraph_0/1/2`. Осмысленный label (напр., главная лемма параграфа)
   — отдельная задача.

## Следующий шаг
1. Вторая L2-стратегия — **кластеризация по `shared_entity`**: связные
   компоненты (или community) в графе L1-метарёбер `shared_entity` →
   L2-метавершина-тема. Ожидание: её L1-фрагменты пересекаются с
   параграфными L2-фрагментами, и `topic_overlap` впервые даст
   непустой результат.
2. Содержательный `label` у L2-метавершины: самая частая значимая лемма
   в фрагменте (после исключения стоп-UPOS), либо head-лемма «центральной»
   клаузы.
3. Когда L2-агрегаторов станет 2+, пересмотреть вопрос generic
   multi-round runner'а и единого протокола `L_k → L_{k+1}`.
