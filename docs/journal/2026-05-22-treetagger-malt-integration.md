# MaltParser + TreeTagger как объяснимый rule/ML-backend morphsyntax

# Лабораторная заметка

**Дата:** 2026-05-22
**Задача:** Достроить заглушку под второй UD-парсер (`morphsyntax.parser: "maltparser"`) до рабочего состояния, объединив `razdel → TreeTagger → MaltParser` в одну цепочку. До изменений ветка `"maltparser"` подавала transition-based парсеру пустые поля морфо-разметки (`_` в колонках 3/4/6 CoNLL-U), что фактически делало её непригодной для исследовательского сравнения с `natasha`.
**Гипотеза:** Классическая связка `razdel → TreeTagger → MaltParser` даёт полностью объяснимый baseline без нейросетевых эмбеддингов (CLAUDE.md §3): TreeTagger — decision-tree теггер (Schmid, 1994) с MSD-Russian параметрами (Sharoff & Nivre), MaltParser — SVM/perceptron transition-based parser (Nivre, 2003). Ожидается, что качество разметки на стандартном UD-SynTagRus будет сопоставимо с `natasha` и при этом полностью трассируемо — каждое решение о POS, лемме или зависимости можно объяснить через явное правило/таблицу, а не через скрытое состояние модели.
**Что изменено:**
- `MorphSyntaxConfig` ([src/metagraph_nlp/config.py:35-89](src/metagraph_nlp/config.py)) — добавлены поля `tree_tagger_bin`, `tree_tagger_param`, `tree_tagger_tagset`, `malt_deprel_mapping`, `java_bin`; новые поля автоматически попадают в `phase1_hash()` через `model_dump()`.
- Новый словарь `configs/treetagger_tagsets/msd_ru.yaml` — декларативный маппинг главного символа MSD-кода на UPOS и схему позиционного разбора, словари значений `gender/number/case/animacy/tense/aspect/...` и список лемм для override CCONJ→SCONJ. Реальные коды собраны прогоном `tree-tagger.exe` на разнообразном русскоязычном корпусе тестовых предложений (16 + 56 токенов, охватывающих NOUN/PROPN/VERB во всех формах, ADJ, PRON, NUM, ADP, CCONJ/SCONJ, PART, ADV, PUNCT).
- Новый модуль `src/metagraph_nlp/parsers/morphsyntax/treetagger_tagmap.py` — `MsdTagMapper` с longest-prefix lookup и набором чистых функций для семи схем (`noun`, `verb`, `adj`, `pronoun`, `numeral`, `adp`, `simple`); `default_tagset_path()` резолвит имя тегсета относительно корня проекта.
- Новый адаптер `src/metagraph_nlp/parsers/morphsyntax/treetagger_adapter.py` — `TreeTaggerMorph` как subprocess-обёртка над `tree-tagger.exe` / `tree-tagger-russian`. Принципиально **не** реализует `MorphSyntaxParser` Protocol (TreeTagger не даёт head/deprel), а выступает как `morph_provider`. UTF-8 на Windows и macOS обеспечивается через `encoding="utf-8"` в `Popen` + `LC_ALL=C.UTF-8`, `LANG=ru_RU.UTF-8`, `PYTHONIOENCODING=utf-8` в env — без явных `os.name`-веток. Для лемм-маркеров `<unknown>` и случаев, когда лемма совпала с поверхностной формой, применяется pymorphy3-fallback (по паттерну `natasha_adapter._fallback_lemma`).
- Переписан `src/metagraph_nlp/parsers/morphsyntax/maltparser_adapter.py` — старый «слепой» `MaltParserAdapter` заменён классом `TreeTaggerMaltParser`, который реализует `MorphSyntaxParser`. Pipeline на одно предложение: `razdel.tokenize` (с сохранением spans) → `TreeTaggerMorph.tag` → сериализация CoNLL-U с **заполненными** колонками 3/4/6 → subprocess MaltParser → `parse_conllu` → опциональное применение `deprel_mapping`. Функция `parse_conllu` получила параметр `spans`, который позволяет восстанавливать start/end позиционно по `id_in_sent` вместо ломкого `text.find(form, search_pos)` (попутно закрыт баг повторов словоформ типа «он сказал, что он…»).
- `pipeline.get_default_parser` ([src/metagraph_nlp/pipeline.py](src/metagraph_nlp/pipeline.py)) — вынес сборку цепочки в отдельный helper `_build_maltparser_treetagger` с валидацией всех четырёх требуемых путей и точным сообщением о недостающем поле. `_worker_init` переведён на single dict-payload через `MorphSyntaxConfig.model_dump()` — pickle-safe, новые поля больше не требуют менять сигнатуру.

**Результат:** Опция `morphsyntax.parser: "maltparser"` теперь активирует **рабочую** цепочку. Все 112 не-slow тестов suite зелёные. Главный contract задачи — отсутствие пустых полей в CoNLL-input для MaltParser — закрыт тестом и подтверждается реальным прогоном TreeTagger (например, для «Студент читает книгу.» получаются коды `Ncmsny → NOUN+Gender=Masc+Number=Sing+Case=Nom+Animacy=Anim`, `Vmip3s-a-e → VERB+VerbForm=Fin+Mood=Ind+Tense=Pres+Person=3+Number=Sing+Voice=Act+Aspect=Imp`, `Ncfsan → NOUN+Gender=Fem+Number=Sing+Case=Acc+Animacy=Inan`). Архитектурно код полностью кросс-платформенен: различия Windows/macOS только в значении путей в YAML, в исходном коде нет ни одной `os.name`-ветки.
**Ограничения:**
- MSD-словарь `msd_ru.yaml` покрывает основные коды, собранные в первом реальном прогоне; редкие или диалектные коды попадают в `(X, {})`. Словарь итеративно дополнять при появлении пробелов.
- Готовой `.mco`-модели MaltParser для русского UD-SynTagRus в публичном доступе нет. Пользователь обучает её локально командой `java -jar maltparser-1.9.2.jar -c ru_syntagrus -m learn -i ru_syntagrus-ud-train-a.conllu -if appdata/dataformat/conllu.xml -a nivreeager` (~20-40 минут CPU). До обучения end-to-end прогон через CLI невозможен.
- Performance: оба subprocess стартуют per-sentence через tempfile (как было в исходном MaltParser). На больших документах это медленно. Persistent subprocess (`tree-tagger-flush.exe` для TreeTagger, `MaltParserService` для MaltParser) запланирован отдельной задачей.
- macOS-проверка не выполнена (рабочая среда Windows). Тестов на macOS-специфику нет, но и os-веток в коде нет — корректность зависит только от правильной установки бинарей и UTF-8 локали.

Сравнить `parsed_sentences.jsonl` с `natasha`-baseline по трём метрикам: совпадение `pos`, совпадение `head`+`deprel` пары (UAS+LAS), время. При обнаружении систематических `pos: X` — дополнить `msd_ru.yaml`.

⚠ Это изменение затрагивает **трассируемость (text traceability)** и **допустимые методы pipeline**. Восстановление `start`/`end` в `parse_conllu` через razdel-spans вместо `text.find` укрепляет инвариант §9.1 (text traceability) на случаях с повторами словоформ; ранее offsets могли быть некорректными. Добавление TreeTagger как нового статистического инструмента остаётся в рамках §3 «классические и вспомогательные ML-методы», но расширяет состав допустимых компонентов и должно быть отражено в разделе диплома, посвящённом архитектуре morphsyntax-слоя.

## Фрагмент для диплома

В качестве альтернативы основному морфо-синтаксическому парсеру (natasha) в pipeline интегрирована классическая цепочка `razdel → TreeTagger → MaltParser`, где каждый компонент представляет собой объяснимый статистический инструмент: TreeTagger использует решающие деревья (Schmid, 1994) с параметрами MSD-Russian (Sharoff & Nivre, 2011) для морфо-разметки и лемматизации, а MaltParser — transition-based dependency parser (Nivre, 2003) — строит синтаксическое дерево поверх размеченных токенов. В отличие от ранее существовавшей реализации, подававшей MaltParser пустые поля морфо-разметки, новый адаптер `TreeTaggerMaltParser` обеспечивает заполнение колонок CoNLL-U значениями `lemma`, UPOS и feats, что критично для корректной работы transition-based алгоритма. Маппинг MSD-кодов на универсальную таксономию UD реализован декларативно через YAML-словарь и набор чистых функций для семи частеречных схем, что обеспечивает воспроизводимость и заменяемость тегсета без изменений кода. Кроме того, в функции восстановления токенных offsets выполнена замена эвристики `text.find` на позиционное соответствие через индексы токенизатора, что устраняет потерю трассируемости на повторах словоформ и укрепляет инвариант text traceability (CLAUDE.md §9.1). Получившийся backend позволяет провести количественное сравнение двух подходов к UD-разбору русского текста — нейросетевого (natasha) и классического — на одной кодовой базе и одних и тех же артефактах pipeline.
