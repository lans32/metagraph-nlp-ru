# np_collapse_v1 — корректная свёртка именных групп через UD-subtree

# Лабораторная заметка

**Дата:** 2026-05-22
**Задача:** Свёртка именных групп (`np_collapse_v0`) находила почти ничего из очевидных NP в тексте: на 4-абзацном тесте с десятками NP («молодой исследователь», «филологический факультет», «научный руководитель», «небольшой кабинет», «русские клаузы») сработала только одна свёртка — «клауза анализ», причём в неправильном порядке.
**Гипотеза:** проблема не в новом backend'е TreeTagger+MaltParser (он выдаёт корректные UD-deprel `amod`/`nmod`/`appos`/`nummod`), а в архитектуре самого правила: (1) `build_semantic_graph` создаёт узлы только для subj/obj/obl/nmod — прилагательных в графе нет вообще, поэтому свёртка через lookup-по-лемме узлов-модификаторов ничего не находит; (2) составная лемма формируется как `[mods] + [head]` — для правых nmod даёт «клауза анализ» вместо «анализ клауза»; (3) `_find_token_by_lemma` ломок на повторах словоформ; (4) нет fixed-point — вложенные модификаторы не обрабатываются.
**Что изменено:**
- [src/metagraph_nlp/graph_builders/np_collapse.py](src/metagraph_nlp/graph_builders/np_collapse.py) полностью переписан как `np_collapse_v1`. Логика:
  - идёт по NOUN/PROPN-узлам графа;
  - получает head-Token напрямую через `parsed.by_id(Node.token_id_in_sent)` — без lookup-по-лемме;
  - рекурсивный BFS subtree-модификаторов с фильтром по `include_deprels` (fixed-point не нужен, вложенные модификаторы собираются за один проход);
  - сортирует head + модификаторы по `Token.id_in_sent`;
  - формирует составную лемму и surface;
  - сохраняет `original_lemma` / `original_upos` (паттерн из `anaphora_resolution_v1`);
  - топология графа не меняется — обновляется только сам NOUN-узел.
- [src/metagraph_nlp/config.py](src/metagraph_nlp/config.py) — новое поле `AggregationConfig.np_collapse_deprels` с дефолтом `[amod, det, nummod, appos, flat, flat:name, nmod:poss]`. Можно сузить/расширить через YAML.
- [src/metagraph_nlp/graph_builders/from_clause.py](src/metagraph_nlp/graph_builders/from_clause.py) `_expand_nmod` теперь пропускает `nmod:poss`, чтобы не дублировать узлы (posессив сворачивается в np_collapse_v1, остальные nmod остаются отдельными сущностями).
- [src/metagraph_nlp/pipeline.py:330-337](src/metagraph_nlp/pipeline.py) — проброс `include_deprels=set(cfg.aggregation.np_collapse_deprels)` в `collapse_noun_phrases`.
- [tests/unit/test_np_collapse.py](tests/unit/test_np_collapse.py) полностью переписан: 13 тестов на новую логику. Главный — `test_right_modifier_via_appos` («исследователь Иван» → «исследователь иван», а не «иван исследователь»). Также покрыты flat:name, nummod, повтор лемм, nmod-non-poss НЕ сворачивается, original_lemma, provenance, override include_deprels.
**Результат:** На том же тексте, что давал 1 свёртку («клауза анализ» в неправильном порядке), теперь — **10 свёрток** в правильном порядке: `молодой исследователь иван`, `ранний осень`, `первый день`, `филологический факультет`, `небольшой кабинет`, `русский клауза`, `этот тема`, `предстоящий работа`, плюс ещё две. Главный пример пользователя теперь корректен: вместо неправильного «клауза анализ» — узел `анализ` остаётся самостоятельным (через `_expand_nmod`), а отдельная свёртка `русский клауза` собрана из `клаузы` + её `amod=русских`. Все 156 тестов suite зелёные (149 → 156).
**Ограничения:**
- Если у NOUN есть `acl`-причастие («известный своими работами») — оно сейчас не сворачивается, но иногда захватывается под `flat`/`appos`, давая странные леммы вида «профессор морозов известный». Чтобы лечить — либо добавить `acl` в `np_collapse_deprels`, либо ограничить включение по POS модификатора (например, исключить VERB).
- `nmod:poss` для PRON-модификаторов («его интересах») даёт леммы вида «он интерес». Семантически спорно — это микрооптимизация на будущее (исключать PRON из модификаторов nmod:poss).
- Если на старых артефактах (до этого изменения) в `provenance.rule` стоит `np_collapse_v0`, они не пересчитываются автоматически — нужна re-run pipeline.
- Decision: `nmod` без `:poss` намеренно НЕ сворачивается. Это сознательное архитектурное решение (CLAUDE.md §5.2): «анализ клауз» — это две связанные сущности, а не одна. Кто хочет агрессивнее — расширяет конфиг.
**Следующий шаг:** Прогнать pipeline на нескольких разнообразных текстах, собрать статистику свёрток (доля NOUN/PROPN, у которых нашлись модификаторы). При обнаружении систематических странностей (`acl`-причастия, PRON-посессивы) — выпустить `np_collapse_v2` с более тонкими правилами.

⚠ Это изменение затрагивает **инвариант «no silent collapse» (CLAUDE.md §9.4)** и **трассируемость**: новая версия правила сохраняет `original_lemma`/`original_upos` и пишет `modifier_token_ids` в `provenance.notes` — каждая свёртка теперь полностью объяснима и обратима. Также затрагивается **`from_clause._expand_nmod`** (исключён `nmod:poss`) — это меняет состав узлов графа на старых текстах, имеющих posессивные nmod. Архитектурное решение про «`nmod` без `:poss` НЕ сворачивается» стоит зафиксировать в разделе диплома про стратегии агрегации.

## Фрагмент для диплома

В правило свёртки именных групп (`np_collapse`) внесены принципиальные изменения, оформленные как версия `v1`. Главный архитектурный пересмотр: новая версия не требует, чтобы все потенциальные NP-модификаторы были предварительно созданы как самостоятельные узлы семантического графа. Вместо этого она читает UD-subtree модификаторов напрямую из объекта `ParsedSentence`, используя якорь `Node.token_id_in_sent`, который указывает на исходный токен. Этот подход устраняет два класса ошибок прежней реализации: (1) пропуск модификаторов, не вошедших в граф (прилагательные, детерминеры, аппозиции и числительные ранее не создавались как узлы и были недоступны для свёртки), и (2) ошибочный порядок в составной лемме при правых модификаторах. Сортировка участников свёртки по `Token.id_in_sent` даёт лемму, соответствующую исходному словопорядку, а рекурсивный обход поддерева позволяет за один проход собирать вложенные модификаторы без явного fixed-point. Список включаемых UD-deprel вынесен в конфигурацию (`AggregationConfig.np_collapse_deprels`), что даёт исследовательскую гибкость — например, агрессивно сворачивать определительные причастия (`acl`) или, наоборот, исключать числительные. Принципиальное решение оставлено: `nmod` без подтипа `:poss` (генитивная группа «анализ клауз») рассматривается как связь между двумя самостоятельными сущностями, выраженная ребром, а не как единая метавершина. Каждая свёртка трассируема — исходная лемма головы сохраняется в `Node.original_lemma`, а список token-id всех модификаторов фиксируется в `Provenance.notes`, что соответствует инварианту проекта «no silent collapse» (CLAUDE.md §9.4). На референсном тексте новое правило увеличило число обнаруженных NP-групп с одной до десяти при сохранении корректности порядка.
