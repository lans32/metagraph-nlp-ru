# 2026-04-16 — UD-разбор, настоящие клаузы, метарёбра, леммы

## Задача
Перейти от MVP-заглушек (клауза=предложение, наивный граф по суффиксам
глаголов, пустые метарёбра) к первой честной лингвистически-обоснованной
версии: UD-парсер → настоящие клаузы → реальный граф с ролями → метарёбра
уровня 1 по общим сущностям. И добавить жёсткое требование: **все метки
узлов — в начальной форме (лемме)**.

## Гипотеза
Если морфо-синтаксический разбор изолирован за протоколом `MorphSyntaxParser`,
граф-билдер и экстрактор клауз работают на нашем внутреннем `ParsedSentence`,
а лемматизация идёт через natasha + pymorphy3-fallback, то:
- весь верхний pipeline не зависит от конкретного парсера и легко тестируется
  с fake-разбором;
- одинаковые сущности в разных клаузах имеют одинаковые метки — что немедленно
  включает агрегацию по общим леммам.

## Что сделано

### Morphsyntax-слой
- Новый модуль `src/metagraph_nlp/parsers/morphsyntax/`:
  - `types.py` — внутренние `Token` и `ParsedSentence` с методами `root()`,
    `children_of`, `by_id`, `subtree_ids(..., stop_deprels)`. Это интерфейс
    между парсером и верхним слоем, не часть доменной модели.
  - `base.py` — `Protocol` `MorphSyntaxParser` с единственным методом
    `parse(sentence_text) -> ParsedSentence`.
  - `natasha_adapter.py` — реализация через natasha (Segmenter, NewsEmbedding,
    NewsMorphTagger, NewsSyntaxParser, MorphVocab). Ленивая инициализация
    через `get_natasha_parser()` (синглтон на процесс).
  - **pymorphy3-fallback для лемматизации**: если natasha вернула
    `lemma == text` для слова с кириллицей, идёт второй проход через
    pymorphy3. Это лечит случаи, когда natasha пометила токен как `pos=X` и
    morph_vocab.lemmatize не сработал (например, «теорему» в одной позиции
    попадало в `X`, в другой — в `NOUN`).
- `scripts/warmup_natasha.py` — одноразовый скрипт, который скачивает веса
  Navec/Slovnet в `~/.natasha/` и прогоняет тестовое предложение.

### Domain
- `Node.lemma`, `Node.surface`, `Node.upos` — опциональные поля.
  **Правило**: `label` теперь **всегда** равно `lemma` (начальная форма).
  Surface сохраняется отдельно для трассируемости.
- `Clause.head_lemma` — лемма предикативного центра клаузы.

### Клаузы (стратегия `ud_subtree_clauses_v0`)
- Новая стратегия: клауза = поддерево финитного VERB. Вложенные клаузы
  (`ccomp`, `xcomp`, `advcl`, `acl`, `acl:relcl`) «вырезаются» из поддерева
  родителя и становятся отдельными клаузами. Однородные сказуемые (`conj`)
  тоже идут отдельными клаузами.
- Старая стратегия `sentence_as_clause_v0` сохранена: активируется через
  конфиг и используется как fallback, если в предложении не найден
  финитный VERB.
- 6 юнит-тестов с фейковыми `ParsedSentence` (natasha не требуется):
  простое, сложносочинённое (conj → 2 клаузы), сложноподчинённое (ccomp →
  2 клаузы), fallback, legacy-стратегия, `parsed_sentences=None`.

### Семантический граф (билдер `ud_roles_v0`)
- Полностью переписан `graph_builders/from_clause.py`:
  - для каждой клаузы находится root-предикат (по `head_lemma` или
    `parsed.root()`);
  - поддерево клаузы собирается через `subtree_ids(..., stop_deprels=…)`;
  - прямые дети предиката классифицируются по UD-ролям: `nsubj`/`nsubj:pass`
    → субъект; `obj`/`iobj` → объект; `obl`/`obl:*` → обстоятельство;
  - Node: `label = lemma`, `surface = token.text`, `upos = token.pos`,
    `kind = "entity"` для PROPN иначе `"concept"`;
  - Edge от субъекта к каждому объекту/обстоятельству; `relation` = лемма
    предиката, а при наличии предлога (`case`-потомок) — `f"{pred}_{prep}"`
    (например, `читать_в`).
- 4 юнит-теста с фейковым парсером: простая SVO-триада, предложная группа,
  `label==lemma` и `surface` сохранён, PROPN → `kind="entity"`.

### Агрегатор метарёбер (`shared_entity_by_lemma_v0`)
- Новый `aggregators/shared_entity_metaedges.py`. Для каждой пары
  метавершин уровня 1 находятся общие леммы из `graph.nodes`. На каждую
  общую лемму создаётся `MetaEdge(type="shared_entity", level=1,
  relation=lemma)` с `provenance.inputs`, перечисляющим все участвующие
  Node id. Фильтр по `exclude_upos` (PRON/DET/ADP/AUX/CCONJ/SCONJ/PART) и
  `min_lemma_len=3`. Детерминизм — через сортировку пар и лемм.
- 5 юнит-тестов: корректность, фильтр PRON, фильтр коротких лемм,
  детерминизм, накопление в `metagraph.meta_edges`.

### Конфиг и pipeline
- `Config.morphsyntax.parser`, `Config.clauses.strategy`, `Config.graph.builder`,
  `Config.aggregation.shared_entity_*`. `configs/default.yaml` обновлён.
- `pipeline.run` теперь принимает `parser: MorphSyntaxParser | None`. Если
  не передали — лениво создаётся natasha-синглтон. Стадия `parse`
  разбирает каждое предложение и собирает `parsed_sentences` (`dict[sent_id,
  ParsedSentence]`), который пробрасывается в clause extractor и graph
  builder. Добавлена стадия `shared_entity_by_lemma_v0` после агрегации.

### Viz
- Тултипы узлов теперь показывают `лемма ← surface` (если разные), `upos`
  и правило происхождения. Это делает визуальную отладку лемматизации
  немедленной.

### Тесты
- `pytest -m 'not slow'` — 24 теста (фейковые парсеры, быстрый прогон,
  без natasha). Зелёные.
- `pytest -m slow` — 5 тестов: адаптер natasha + интеграция thin-slice
  (полный pipeline с настоящим natasha + viz). Зелёные.
- В `pyproject.toml` зарегистрирован маркер `slow`; `addopts = "-m 'not slow'"`
  по умолчанию скрывает медленные тесты от обычного прогона.

## Результат
`PYTHONPATH=src python -m metagraph_nlp process --input data/samples/short.txt
--out artifacts/runX --viz --config configs/default.yaml` на обогащённом
sample-тексте («Студент читает книгу. Преподаватель объясняет студенту
теорему. Студент анализирует теорему на лекции.»):

- 3 предложения → 3 клаузы с `head_lemma` {читать, объяснять, анализировать};
- 7 узлов, все с `label` в начальной форме (`студент`, `книга`,
  `преподаватель`, `теорема`, …) и с `surface` исходного текста;
- 4 ребра: `читать`, `объяснять` (×2 — obj и iobj), `анализировать`;
- 3 метавершины уровня 1 + **4 метаребра `shared_entity`**: 3 × `студент`
  (A-B, A-C, B-C) и 1 × `теорема` (B-C).

В `metagraph.html` метавершины связаны жирными стрелками по общим сущностям,
и это хорошо видно.

## Ограничения
1. **natasha нестабильно помечает POS**. Иногда выдаёт `X` вместо `NOUN`
   для вполне обычных слов. Лечится pymorphy3-fallback для лемм, но
   синтаксическая структура от этого не улучшается. Если `pos=X`, узел
   может попасть в граф с неправильной ролью или не попасть вовсе.
2. **obl на предлогах**. natasha иногда вешает предложную группу не как
   `obl` на глагол, а как `nmod` на существительное. Наш граф-билдер таких
   не подхватывает. Это приемлемо для MVP, но стоит покрыть в следующей
   итерации.
3. **conj-предикаты**. Сейчас выделяются как отдельные клаузы, но общие
   аргументы («Студент читал и писал») обе клаузы наследуют только тот
   аргумент, на который показывает их собственный `nsubj`. Если subject
   шарится через conj, второй VERB останется без субъекта.
4. **shared_entity — только по точной лемме**. Синонимы, кореференция и
   морфологические омонимы не учитываются. Это осознанно — кореференция
   отдельная большая задача (out of scope).
5. **Структурная (§5.2) и семантическая (§5.3) агрегация** выключены.

## Следующий шаг
1. Улучшить граф-билдер: подхватывать `nmod`-подгруппы существительных
   (предложные группы) как дополнительные узлы/рёбра; обрабатывать
   общие субъекты при conj.
2. Добавить кореференцию через местоимения как второй тип метарёбер.
3. Начать думать о втором уровне метаграфа: агрегаты метавершин-клауз в
   метавершины-параграфы или темы. Сейчас, когда уровень 1 даёт реальные
   связи, появляется материал для второго уровня.
