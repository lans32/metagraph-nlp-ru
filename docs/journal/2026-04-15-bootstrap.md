# 2026-04-15 — Bootstrap проекта

## Задача
Поднять каркас исследовательского проекта `metagraph-nlp-ru` и запустить
первую сквозную «тонкую нитку» pipeline от сырого текста до тривиального
метаграфа.

## Гипотеза
Если с самого начала зафиксировать явные доменные типы (Document, Sentence,
Clause, Node, Edge, MetaNode, MetaEdge, GraphFragment, Metagraph, Provenance)
и провести через них минимальный проход `text → sentences → clauses → graph →
metagraph`, дальнейшая работа над правилами выделения клауз, построения графа
и агрегации будет сводиться к замене отдельных заглушек без перестройки
архитектуры.

## Что сделано
- Создан каркас пакета `src/metagraph_nlp/` по §12 CLAUDE.md
  (`domain`, `parsers`, `graph_builders`, `aggregators`, `transforms`,
  `io`, `provenance`, `profiling`, `pipeline`, `cli`).
- Реализована доменная модель на pydantic v2. Метавершины и метарёбра —
  полноценные объекты с `level`, `type`, `fragment`, `provenance`
  (инварианты §9.2, §9.3).
- Реализован первый проход pipeline:
  - `normalize_text` — детерминированная нормализация (NFC, кавычки, тире,
    пробелы);
  - `split_sentences` — сегментация через `razdel.sentenize`;
  - `extract_clauses` — **временно** clause=sentence (см. «Ограничения»);
  - `build_semantic_graph` — наивный билдер: на клаузу до двух узлов и одно
    ребро-предикат по грубой эвристике глагольных окончаний;
  - `aggregate_clauses_to_metanodes` — лингвистическая агрегация уровня 1:
    каждая клауза → `MetaNode(type="clause", level=1)` с полным
    `GraphFragment` и provenance.
- Добавлены `AuditLog` (JSONL) и сериализация всех промежуточных артефактов
  в `artifacts/<run>/` (document, sentences, clauses, graph, metagraph,
  audit, снапшот конфига с его хэшем).
- CLI `python -m metagraph_nlp process --input … --out …`.
- Юнит-тесты на domain и нормализацию, интеграционный тест на сквозной
  проход и запись артефактов.

## Результат
Pipeline воспроизводимо прогоняется на `data/samples/short.txt` и
выдаёт непустые артефакты. Каждый элемент модели несёт `provenance` с
указанием правила, стадии и предшествующих входов — инвариант §9.1
(text traceability) соблюдён.

## Ограничения (осознанные заглушки)
1. **Клаузы.** Стратегия `sentence_as_clause_v0`: одна клауза на предложение.
   Это явная временная мера — реальная логика выделения клауз (предикативный
   центр, сложноподчинённые конструкции, однородные сказуемые) будет
   добавлена отдельной задачей под skill `rule-based-clause-extractor`.
2. **Семантический граф.** Билдер `naive_head_dep_v0` опирается на суффиксную
   эвристику глаголов, без морфологического и синтаксического анализа. Это
   заглушка для формы данных, а не лингвистическая модель. Переход на UD-парсер
   (natasha / spacy-ru) — отдельная задача под skill `semantic-graph-builder`.
3. **Агрегация.** Работает только лингвистическая стратегия §5.1 уровня 1.
   Метарёбра пока не создаются. Структурная (§5.2) и семантическая (§5.3)
   агрегация выключены в конфиге.
4. **OCR.** Не реализован; это отдельный изолированный этап (§6).

## Следующий шаг

2. После этого — первая честная версия выделения клауз (сложные предложения,

3. Ввести первые метарёбра уровня 1 между MetaNode-клаузами (например,
   кореферентные связи или общие сущности).
