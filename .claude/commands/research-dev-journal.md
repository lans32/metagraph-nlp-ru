Ты помогаешь вести исследовательский дневник разработки для проекта по построению метаграфового представления русскоязычного текста. Проект ведётся в рамках дипломной работы. Каждая запись накапливает материал для диплома и научных статей.

## Шаг 1. Получи описание изменения

Если `$ARGUMENTS` не пустой — используй это как описание изменения или темы записи.

Если `$ARGUMENTS` пустой — спроси пользователя:
> «Опиши, что было сделано или изменено в этой сессии. Что ты исследовал, что добавил, что исправил?»

## Шаг 2. Изучи реальные изменения в коде

Выполни следующие команды, чтобы понять, что фактически изменилось:

```
git diff HEAD~1
git log --oneline -5
git status
```

Если изменений в git нет — работай только с описанием от пользователя.

## Шаг 3. Задай уточняющие вопросы (если нужно)

Если из описания и git-диффа неясно следующее — задай вопросы:

- Какова была исследовательская мотивация этого изменения?
- Что именно тестировалось или проверялось?
- Каков результат — ожидаемый или неожиданный?
- Остались ли нерешённые вопросы или ограничения?
- Какой следующий шаг планируется?

Не задавай вопросы, если ответы уже очевидны из контекста.

## Шаг 4. Сформируй обе записи

### Запись 1: Лабораторная заметка

Строгий формат, все поля обязательны:

```
# Лабораторная заметка

**Дата:** ГГГГ-ММ-ДД
**Задача:** [одна строка — что решалось]
**Гипотеза:** [что ожидалось увидеть или проверить]
**Что изменено:** [конкретно — файлы, модули, правила, структуры]
**Результат:** [что получилось — с конкретикой]
**Ограничения:** [что не работает, что не проверено, что может сломаться]
**Следующий шаг:** [конкретное действие]
```

### Запись 2: Абзац для диплома

Короткий академический фрагмент (3–6 предложений), пригодный для вставки в диплом или статью. Пиши в академическом стиле, от третьего лица или безлично. Используй терминологию проекта: клауза, метавершина, метаребро, семантический граф, агрегация, provenance, правило, pipeline.

Типичные темы абзаца:
- изменение правил выделения клауз
- изменение модели метавершины или метаребра
- новая стратегия агрегации
- обнаруженная ошибка в интерпретации предиката
- разница между структурной и лингвистической агрегацией
- ограничение OCR
- сравнение двух подходов к разбору

## Шаг 5. Предупреждение об инвариантах

Проверь, затрагивает ли изменение хотя бы один из следующих аспектов:

- инварианты модели (метавершина, метаребро, provenance, идентификаторы)
- правила агрегации (новые правила, изменение существующих, удаление)
- интерпретацию клаузы (что считается предикативным центром, границы клаузы)
- допустимые методы (новый инструмент, ML-компонент, отступление от rule-based подхода)
- трассируемость (text traceability, lineage, audit trail)

Если да — добавь явное предупреждение:

```
⚠ Это изменение затрагивает [название аспекта]. Рекомендуется зафиксировать
архитектурное решение отдельно и отразить его в соответствующем разделе диплома.
```

## Шаг 6. Сохрани запись в файл

Предложи имя файла в формате:

```
journal/ГГГГ-ММ-ДД-<краткая-тема-латиницей-или-по-русски>.md
```

Примеры:
- `journal/2025-03-10-clause-extraction-rules.md`
- `journal/2025-03-15-metavertex-model-update.md`
- `journal/2025-03-20-aggregation-provenance.md`

Создай директорию `journal/` если она не существует. Создай файл с обеими записями — лабораторной заметкой и абзацем для диплома — объединёнными в один документ.

Структура файла:

```markdown
# [Краткое название темы]

[Лабораторная заметка]

---

## Фрагмент для диплома

[Абзац]
```

После создания файла сообщи пользователю путь к файлу и кратко напомни, если было предупреждение об инвариантах.
